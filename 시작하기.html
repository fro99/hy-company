이 HY컴퍼니 프로젝트에서 Vercel CLI, Supabase CLI를 사용해서 연결과 배포를 진행하고 싶어.

나는 처음 해보는 학생이야. 네가 실행할 수 있는 명령은 직접 실행하고, 내가 해야 하는 로그인·계정 선택·비밀번호 입력은 그때그때 한 단계씩 안내해줘. 한꺼번에 모든 일을 시키지 말고 현재 단계의 결과를 확인한 뒤 다음으로 넘어가줘.

1. 현재 폴더의 README.md와 docs/학생시작가이드.md를 읽어줘. package.json이 있는 hy-company 폴더인지 확인하고, Supabase CLI와 Vercel CLI의 설치 상태·버전·--help를 확인해줘. 설치가 필요하면 이 프로젝트에서 사용할 수 있게 준비해줘.
2. Supabase CLI로 로그인하고 내가 사용할 프로젝트를 확인해줘. 없으면 CLI로 새 프로젝트를 만드는 과정을 도와줘. 조직·지역·프로젝트는 내 것을 선택하고, 인증이나 DB 비밀번호는 내가 직접 입력하도록 해줘. 기존 프로젝트를 임의로 새로 만들거나 바꾸지 마.
3. Supabase CLI 초기화가 필요하면 진행하고, supabase/01_hy_company.sql을 확인해서 migrations에 넣을 초기 마이그레이션을 준비해줘. 같은 마이그레이션이 이미 있으면 중복 생성하지 마. 내 프로젝트에 link한 뒤 db push의 dry-run으로 적용 대상을 보여주고 실제로 반영해줘. CLI 3에서는 원격 DB 작업에 --remote가 필요하니 설치 버전의 도움말에 맞춰 실행해줘. db reset은 하지 말고 기존 데이터와 다른 테이블은 유지해줘.
4. 내 Supabase Project URL과 공개용 Publishable key를 .env.local에 연결해줘. secret/service_role 키는 사용하지 말고 실제 키·토큰·DB 비밀번호를 대화나 Git에 남기지 마. 필요한 값만 안전하게 파일에 쓰거나 내가 직접 입력하도록 안내해줘. 서버를 다시 실행하고 /setup에서 실제 Supabase 조회와 공고 표시를 확인해줘. 로컬 예시 모드를 연결 성공으로 처리하지 마.
5. 이 프로젝트가 내 GitHub 저장소에 연결됐는지 확인하고, 없으면 로그인·저장소 생성·첫 커밋과 push를 도와줘. 기존 저장소와 브랜치는 먼저 확인하고 강제 push하지 마. .env.local, .mcp.json, .vercel, supabase/.temp, node_modules, .next는 포함하지 마.
6. Vercel CLI의 login과 link로 현재 폴더를 내 Vercel 프로젝트에 연결해줘. 기존 프로젝트가 있으면 재사용해줘. GitHub push로 자동 배포되도록 vercel git connect도 확인해줘. vercel link만 했다고 GitHub 자동 배포 연결까지 끝났다고 하지 마.
7. Vercel CLI의 env 명령으로 NEXT_PUBLIC_SUPABASE_URL과 NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY를 production 환경에 등록해줘. 이미 있으면 올바른 프로젝트 값인지 확인하고 필요한 것만 갱신해줘. 값은 로그나 대화에 출력하지 마. Preview도 사용할 때는 preview 환경을 따로 설정해줘.
8. 빌드를 확인한 뒤 Vercel CLI로 --prod 배포해줘. Ready와 공개 주소를 확인하고, 공개 사이트의 /setup에서도 Supabase 연결 상태와 실제 공고를 확인해줘. 직접 확인하지 못한 부분은 내가 확인할 방법을 알려줘.

DB 변경은 Supabase CLI로, 코드 배포는 Vercel CLI 또는 연결된 GitHub push로 진행한다는 차이를 쉽게 설명해줘. 아직 “나의 채용 분석” 탭이나 MCP 연결은 만들지 말고, 이 공통 프로젝트의 연결과 첫 배포까지만 진행해줘.
