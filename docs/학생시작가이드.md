# HY컴퍼니 · CLI로 연결하기

## 학생이 할 일

1. ZIP을 풀고 `hy-company` 폴더에서 Claude Code를 엽니다.
2. `npm ci` → `npm run dev`로 서버를 실행하고 터미널 주소의 `/setup`을 엽니다.
3. **CLI 연결 프롬프트 복사** → Claude Code에 붙여넣기 → Enter.
4. AI가 안내하는 인증 주소에서 직접 로그인하고, 본인의 조직·프로젝트를 선택합니다. 명령 실행 승인이 필요한 경우 내용을 확인합니다.
5. 연결 후 로컬 `/setup`에 실제 DB 공고가 보이는지, 배포 후 공개 주소에서도 같은 공고가 보이는지 확인합니다.

Node.js 24 LTS 권장(최소 22). 계정이 없다면 안내된 서비스에서 가입이 필요합니다. 로그인·비밀번호 입력은 학생이 직접 합니다.

## AI가 진행할 순서

### Supabase CLI

- 설치 버전과 도움말 확인 → 로그인 → 프로젝트 확인/생성 → 로컬 설정 초기화 → 프로젝트 link.
- `supabase/01_hy_company.sql`을 원본으로 `supabase/migrations`에 초기 마이그레이션을 준비합니다. 같은 파일이나 적용 이력이 있으면 중복 생성하지 않습니다.
- 원격 프로젝트와 적용할 SQL을 dry-run으로 확인한 뒤 db push로 반영합니다. 기존 테이블과 데이터는 유지하고 db reset은 사용하지 않습니다.
- CLI 3.x의 db 명령은 기본이 로컬이므로 원격에는 `--remote`를 명시합니다. 구버전 옵션을 그대로 복사하지 말고 설치된 `--help`를 확인합니다.
- Project URL·공개용 Publishable key를 `.env.local`에 설정하고 서버를 재시작합니다. 연결 후 표시가 **Supabase 연결됨**으로 바뀌어야 합니다. 미연결 상태의 예시 공고 6건은 DB 연결 성공이 아닙니다.
- 이번 수업은 호스팅된 Supabase를 사용합니다. 로컬 Supabase 스택을 시작하는 `supabase start`나 Docker 설치는 이 연결 흐름의 필수 단계가 아닙니다.

### GitHub와 Vercel CLI

- 내 GitHub 저장소 연결과 첫 commit·push를 확인합니다. 다른 프로젝트나 기존 변경을 덮어쓰지 않습니다.
- Vercel CLI `login` → `link`로 내 프로젝트를 선택/생성합니다.
- GitHub 자동 배포에는 `vercel git connect`가 필요합니다. 로컬 폴더의 `link`와 GitHub 저장소 연결을 구분합니다.
- Vercel CLI `env add` / `env update`로 `NEXT_PUBLIC_SUPABASE_URL`과 `NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY`를 **production** 환경에 설정합니다. `env ls`로 이름과 대상 환경을 확인합니다. Preview를 쓰면 preview 환경도 따로 설정합니다.
- 빌드 확인 → `vercel --prod` → Ready → 공개 주소의 `/setup`과 채용 화면 확인.
- 이후 DB 변경은 Supabase CLI로 따로 적용합니다. GitHub push는 DB 변경을 자동으로 적용하지 않습니다. 연결된 Production Branch에 push하면 Vercel 코드 배포가 시작됩니다.

CLI 명령은 프로젝트에 설치된 도구를 `npx supabase ...`, `npx vercel ...`로 실행합니다. 각 버전의 도움말을 먼저 확인하고 현재 화면에 맞게 안내합니다. 이미 연결된 계정·프로젝트는 재사용합니다.

## 비밀값과 프로젝트 구분

- 공개용 Publishable key만 앱에 사용합니다. secret/service_role 키, DB 비밀번호, 로그인 토큰을 답변·Git에 남기지 않습니다.
- `.env.local`, `.mcp.json`, `.vercel`, `supabase/.temp`, `node_modules`, `.next`는 Git과 배포 ZIP에서 제외합니다.
- 공고 테이블은 `hy_company_jobs`, 홈은 `/`, 상세는 `/jobs/[id]`입니다. 분석 탭과 분석용 테이블은 뒤의 강의에서 별도로 만듭니다.
- Supabase link, 환경변수, Vercel 프로젝트가 모두 본인이 선택한 같은 대상인지 확인합니다. `/setup`의 성공 표시는 DB 조회만 검증하며 GitHub/Vercel 인증을 대신 검증하지 않습니다.
